Features

The parts you actually use.

Not a dashboard. A small, fast surface for the work between a prompt and a merged change.

  • Loopback by default
  • No account
  • No telemetry
  • MIT

The loop

01

Every session, in reach

Search, group, rename, create, and delete sessions. Waiting sessions are visible before you open them.

02

Streaming that reconnects

Follow a turn as it happens, page through older messages, and return to the latest message without losing the thread.

03

Approvals with context

Review the tool, the target, and the diff before you allow it. Destructive actions ask twice.

04

Files, not screenshots

Attach images, camera captures, and documents. Validation happens at the bridge, not only in the UI.

05

Quiet notifications

Optional push for finished turns, questions, and approvals. Payloads carry IDs and generic text, not message bodies.

06

Three languages

English, Arabic, and French, with an RTL layout, mixed-direction text, and a monochrome theme that gets out of the way.

Where it runs

Build with EAS

Expo Router and native modules. Build on macOS or EAS.

Web

Install the PWA

Static export, same-origin proxy, no offline cache of sessions.

Chromium · Firefox · Safari
Host

Run the bridge

Node on Linux, macOS, or Windows. Docker and systemd recipes.

Node 20+

Not included

Deliberately out of scope

Model or agent switching, per-session model choice, a bundled Telegram bot, and a native desktop wrapper. The app shows a telegram source when another OpenCode client is used, but it does not implement one.
