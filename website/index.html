01 / The loop

The parts you actually use.

Not a dashboard. A small, fast surface for the work between a prompt and a merged change.

01

Every session, in reach

Search, group, rename, create, and delete sessions. Waiting sessions are visible before you open them.

02

Streaming that reconnects

Follow a turn as it happens, page through older messages, and return to the latest message without losing the thread.

03

Approvals with context

Review the tool, the target, and the diff before you allow it. Destructive actions ask twice.

04

Files, not screenshots

Attach images, camera captures, and documents. Validation happens at the bridge, not only in the UI.

05

Quiet notifications

Optional push for finished turns, questions, and approvals. Payloads carry IDs and generic text, not message bodies.

06

Bilingual by default

Arabic and English, RTL layout, mixed-direction text, and a monochrome theme that gets out of the way.

02 / The boundary

The network edge is the point.

The app talks to a local bridge. The bridge talks to OpenCode on loopback. Nothing is relayed through a hosted account.

One token. One owner. A deliberately small blast radius.

  • Bearer token with constant-time comparison and failed-auth bans.
  • Workdir allowlist for sessions, uploads, and downloads.
  • Upload type, extension, magic-byte, size, and filename checks.
  • Loopback-only OpenCode URL; Tailscale or a reverse proxy for remote access.
  • No telemetry, no hosted relay, no account system. The landing page reads the public GitHub star count.
  • Opt-in CORS with exact origins. Wildcards are rejected.

04 / The install

Three steps. No account.

Build the bridge, start OpenCode, and point the app at your private address. The installer writes the token; it never prints it.

  1. 01

    Install the bridge

    Download, verify the checksum, and create a private config.

  2. 02

    Start the agent

    Keep OpenCode on loopback. Use Tailscale for the phone.

  3. 03

    Connect once

    Enter the bridge URL and token. The token stays on the device.

06 / The fine print

Questions worth asking.

Is this an official OpenCode app?

No. It is an independent client. The OpenCode name and logo belong to the upstream project. This project is not endorsed by the OpenCode team.

Does my code leave my machine?

The bridge talks to OpenCode on loopback. Your device talks to the bridge over your private network. There is no hosted relay and no telemetry. The landing page reads the public GitHub star count. If you configure a third-party push service, it receives a token and a generic notification payload.

Do I need Tailscale?

Only for remote access. On the same machine, loopback is enough. For a phone on another network, Tailscale or an HTTPS reverse proxy is the supported path.

Is there a Play Store or App Store build?

Not yet. Android is a sideloaded beta. iOS is built with EAS and has no TestFlight track in this repository.

Why is model switching missing?

The first beta focuses on a reliable session loop. Model and agent switching will land only when the upstream API exposes stable endpoints; the roadmap tracks it as a post-beta item.
