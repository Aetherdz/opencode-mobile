Sécurité

Tout se joue à la frontière du réseau.

L’application dialogue avec une passerelle locale. La passerelle dialogue avec OpenCode en loopback. Rien ne transite par un compte hébergé.

La limite de confiance

Appareil Mobile / Web Votre jeton
réseau privé
Hôte Passerelle 127.0.0.1:8787
loopback
Agent OpenCode Votre machine
Un seul jeton Le jeton de la passerelle équivaut à un accès shell sur votre machine. Quiconque le détient peut demander à l’agent de lire des fichiers, d’exécuter des commandes et de modifier du code dans les répertoires de travail autorisés.

Contrôles

  • Jeton bearer comparé en temps constant, avec bannissement après des échecs d’authentification.
  • Tickets WebSocket à usage unique, pour que le justificatif n’apparaisse jamais dans une URL ni dans un journal d’accès.
  • Liste blanche de répertoires de travail pour les sessions, les envois et les téléchargements.
  • Vérifications du type, de l’extension, des octets magiques, de la taille et du nom de fichier à l’envoi.
  • URL OpenCode en loopback uniquement ; Tailscale ou un proxy inverse pour l’accès à distance.
  • Aucune télémétrie, aucun relais hébergé, aucun système de compte.
  • CORS activé sur demande, avec des origines exactes. Les jokers sont refusés.

Le modèle de menace complet, les règles de caviardage et les lacunes connues figurent dans docs/security.md.

Liste de vérification du déploiement

  • AUTH_TOKEN compte au moins 32 caractères aléatoires et est propre à cette passerelle.
  • HOST reste sur 127.0.0.1 ; l’accès à distance passe par Tailscale ou un tunnel.
  • ALLOWED_WORKDIRS ne liste que les racines que vous voulez exposer.
  • CORS_ORIGINS reste vide, sauf si une version navigateur en a besoin.
  • Les fichiers de version sont vérifiés par rapport au fichier SHA256SUMS publié.
  • Le jeton est renouvelé lorsqu’un appareil est perdu ou que la machine est partagée.
