Seguridad

El perímetro de la red es lo que importa.

La aplicación habla con un puente local. El puente habla con OpenCode por loopback. Nada pasa por una cuenta alojada.

Un solo token El token del puente equivale a tener acceso de shell en tu máquina. Quien lo posea puede pedirle al agente que lea archivos, ejecute comandos y modifique código dentro de los directorios de trabajo permitidos.

Controles

  • Token de portador con comparación en tiempo constante y bloqueo tras fallos de autenticación.
  • Tickets de WebSocket de un solo uso, para que la credencial nunca acabe en una URL ni en un registro de acceso.
  • Lista de directorios de trabajo permitidos para sesiones, subidas y descargas.
  • Comprobaciones de tipo, extensión, magic bytes, tamaño y nombre de archivo en las subidas.
  • URL de OpenCode solo por loopback; Tailscale o un proxy inverso para el acceso remoto.
  • Sin telemetría, sin relay alojado y sin sistema de cuentas.
  • CORS opcional con orígenes exactos. Los comodines se rechazan.

El modelo de amenazas completo, las reglas de redacción y las carencias conocidas están en docs/security.md.

Lista de verificación de despliegue

  • AUTH_TOKEN tiene al menos 32 caracteres aleatorios y es exclusivo de este puente.
  • HOST se mantiene en 127.0.0.1; el acceso remoto pasa por Tailscale o un túnel.
  • ALLOWED_WORKDIRS solo enumera las raíces que quieres exponer.
  • CORS_ORIGINS está vacío salvo que alguna compilación para navegador lo necesite.
  • Los archivos de la versión se verifican con el SHA256SUMS publicado.
  • El token se renueva cuando se pierde un dispositivo o se comparte la máquina.
